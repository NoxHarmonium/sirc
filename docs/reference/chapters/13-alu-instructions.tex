\chapter{ALU Instructions}
\label{ch:alu-instructions}

\section{Overview}

The ALU (Arithmetic Logic Unit) instructions perform arithmetic and logical operations on register operands. All ALU
instructions follow the load/store architecture principle: they operate only on registers, not directly on memory.

ALU instructions are available in three format variants:
\begin{itemize}
	\item \textbf{Immediate}: Operation with 16-bit constant
	\item \textbf{Short Immediate with Shift}: Operation with 8-bit constant and optional shift
	\item \textbf{Register}: Operation between registers with optional shift
\end{itemize}

\section{ALU Instruction Families}

\subsection{Arithmetic Instructions}
\begin{itemize}
	\item \mnemonic{ADD} -- Addition
	\item \mnemonic{ADC} -- Add with Carry
	\item \mnemonic{SUB} -- Subtraction
	\item \mnemonic{SBC} -- Subtract with Carry (Borrow)
\end{itemize}

\subsection{Logical Instructions}
\begin{itemize}
	\item \mnemonic{AND} -- Bitwise AND
	\item \mnemonic{ORR} -- Bitwise OR
	\item \mnemonic{XOR} -- Bitwise XOR (Exclusive OR)
\end{itemize}

\subsection{Data Movement}
\begin{itemize}
	\item \mnemonic{MOV} -- Move immediate or copy register
\end{itemize}

\subsection{Test and Compare}
\begin{itemize}
	\item \mnemonic{CMN} -- Compare Negative (add without saving result)
	\item \mnemonic{CNC} -- Compare Negative with Carry (add with carry without saving result)
	\item \mnemonic{CMP} -- Compare (subtract without saving result)
	\item \mnemonic{CPC} -- Compare with Carry (subtract with carry without saving result)
	\item \mnemonic{TSA} -- Test AND (AND without saving result)
	\item \mnemonic{TSO} -- Test OR (OR without saving result)
	\item \mnemonic{TSX} -- Test XOR (XOR without saving result)
\end{itemize}

\noindent\textbf{Register shorthand:} When a register-form ALU instruction omits \texttt{rS1}, the assembler encodes
\texttt{rD} as both the destination and first source operand. For example, \texttt{ADDR r1, r2} is encoded as
\texttt{ADDR r1, r1, r2}. A shift definition may be combined with the shorthand; because the shift always applies to
the left operand, \texttt{ADDR r1, r2, LSL \#2} computes \texttt{(r1 << 2) + r2}, not \texttt{r1 + (r2 << 2)}.

\noindent\textbf{Short-immediate move:} Opcode \opcode{27} has no public assembly syntax and is undocumented.

\section{Common ALU Semantics}

\begin{table}[H]
	\centering
	\begin{tabular}{lp{9cm}}
		\toprule
		\textbf{Topic}         & \textbf{Definition}                                                                                                                                                                   \\
		\midrule
		Condition false        & The instruction is skipped and has no side effects. Registers and status flags are preserved.                                                                                         \\
		Immediate format       & The left operand is the named register. The right operand is the encoded 16-bit immediate.                                                                                            \\
		Short immediate format & The left operand is the named register after the encoded shift is applied. The right operand is the encoded 8-bit immediate.                                                          \\
		Register format        & The left operand is \texttt{rS1} after the encoded shift is applied. The right operand is \texttt{rS2}.                                                                               \\
		Test variants          & \mnemonic{CMN}, \mnemonic{CNC}, \mnemonic{CMP}, \mnemonic{CPC}, \mnemonic{TSA}, \mnemonic{TSO}, and \mnemonic{TSX} compute a result for flag updates but do not write it back.        \\
		MOV                    & \mnemonic{MOVI} and \mnemonic{MOVR} write the selected operand to \texttt{rD}.                                                                                                        \\
		Timing                 & ALU instructions complete in 6 cycles, plus any instruction-fetch wait states.                                                                                                        \\
		Exceptions             & Raises no data-memory faults. In protected mode, an ALU instruction that writes a privileged high address register raises a privilege-violation fault at decode; see the notes below. \\
		\bottomrule
	\end{tabular}
	\caption{Common ALU Semantics}
	\label{tab:alu-common-semantics}
\end{table}

\noindent ALU instruction execution does not perform data-memory access and does not raise data bus, data
bus-protection, data alignment, effective-address segment-overflow, or invalid-opcode faults. An ALU instruction in the
last instruction slot of a segment still raises a segment-overflow fault when \texttt{SR.A} is set, because it
advances the program counter, unless it writes \reg{pl} (Section~\ref{sec:segment-overflow-fault}). In protected mode, an ALU instruction that
writes \reg{ah}, \reg{lh}, \reg{ph}, or \reg{sh} through its register field raises a privilege-violation fault at
decode and has no other effect; compare and test instructions only read that field and never fault. An ALU instruction whose register field names \reg{sr} is permitted in protected mode, but only
bits 7--0 of \reg{sr} are written; bits 15--8 are left unchanged (Section~\ref{sec:sr-manual-updates}). Instruction fetch can still raise the normal fetch faults before an ALU instruction executes.
If trace mode was enabled when the instruction began, an instruction-trace fault is raised after the instruction
commits. Every 6-bit opcode decodes; no processing-unit encoding raises an invalid-opcode fault. Encodings outside the
documented ALU forms execute with architecturally undefined results (see Appendix~\ref{appendix:undocumented}).

\section{Status Flag Updates}

ALU instructions update the status register flags:

\begin{description}
	\item[Arithmetic (ADD, ADC, SUB, SBC, CMN, CNC, CMP, CPC)] Update all four flags: N, Z, C, V
	\item[Logical and move (AND, ORR, XOR, TSA, TSO, TSX, MOVI, MOVR)] Update N and Z; clear C and V
\end{description}

\begin{table}[H]
	\centering
	\begin{tabular}{llllllp{5.5cm}}
		\toprule
		\textbf{Family} & \textbf{N} & \textbf{Z} & \textbf{C} & \textbf{V} & \textbf{Default AF} & \textbf{Meaning}                                                   \\
		\midrule
		ADD             & *          & *          & *          & *          & \texttt{[A]}        & C is carry out; V is signed overflow.                              \\
		ADC             & *          & *          & *          & *          & \texttt{[A]}        & Adds incoming C; C is carry out.                                   \\
		SUB             & *          & *          & *          & *          & \texttt{[A]}        & C is set when a borrow occurs.                                     \\
		SBC             & *          & *          & *          & *          & \texttt{[A]}        & Subtracts incoming C as borrow input; C is set on outgoing borrow. \\
		CMN             & *          & *          & *          & *          & \texttt{[A]}        & Same flags as ADD; result is discarded.                            \\
		CNC             & *          & *          & *          & *          & \texttt{[A]}        & Same flags as ADC; result is discarded.                            \\
		CMP             & *          & *          & *          & *          & \texttt{[A]}        & Same flags as SUB; result is discarded.                            \\

		TSA             & *          & *          & 0          & 0          & \texttt{[A]}        & Same flags as AND; result is discarded.                            \\
		TSO             & *          & *          & 0          & 0          & \texttt{[A]}        & Same flags as ORR; result is discarded.                            \\
		TSX             & *          & *          & 0          & 0          & \texttt{[A]}        & Same flags as XOR; result is discarded.                            \\
		MOV             & *          & *          & 0          & 0          & \texttt{[A]}        & C and V are cleared.                                               \\

	\label{tab:alu-status-flag-effects}
\end{table}

See Table~\ref{tab:flag-effect-symbols} for the flag-effect symbol definitions. The table shows the effect when the
instruction uses its default status update source. If \texttt{[N]} is encoded, all status flags are preserved. If
\texttt{[A]} is encoded, flags are updated from the ALU result according to the instruction family. If \texttt{[S]} is
encoded, flags are updated from the shifter result instead of the ALU result; see Chapter~\ref{ch:shift-operations} for
the shifter flag rules. The immediate format has no shift fields, so \texttt{[S]} on an immediate-format instruction
clears N, Z, C and V; reserved bits 7--4 follow the rule in Chapter~\ref{ch:status-register}. Use \texttt{[S]} only
with short-immediate and register forms. An immediate written without a shift suffix always assembles to the immediate
format, even when it fits in 8 bits, so \texttt{ADDI[S] r1, \#10} clears the flags; write \texttt{ADDI[S] r1, \#10, NUL
	\#0} to get the short-immediate format and flags from the shifter. \mnemonic{MOVI} and \mnemonic{MOVR} have no shifted
operand and do not accept \texttt{[S]}; an encoding of those opcodes with AF \texttt{10}, which is not reachable from
public assembly syntax, leaves all four status flags architecturally undefined (\texttt{U U U U}).

\subsection{Flag Computation Formulas}

Table~\ref{tab:alu-status-flag-effects} states which flags each family updates; this section states exactly how, as a
Boolean formula in terms of the sign bit (bit 15) of the destination operand (\texttt{Dm}), the source operand
(\texttt{Sm}), and the result (\texttt{Rm}). $\cdot$ is Boolean AND, $+$ is Boolean OR, and $\overline{X}$ is the
complement of $X$.

\begin{table}[H]
	\centering
	\begin{tabular}{lp{4.2cm}p{4.2cm}}
		\toprule
		\textbf{Family}              & \textbf{C}                                                      & \textbf{V}                                                                     \\
		\midrule
		ADD, ADC, CMN, CNC           & Carry out of bit 15 of the full addition                        & $Dm \cdot Sm \cdot \overline{Rm} + \overline{Dm} \cdot \overline{Sm} \cdot Rm$ \\
		SUB, SBC, CMP, CPC           & $\overline{Dm} \cdot Sm + Sm \cdot Rm + Rm \cdot \overline{Dm}$ & $Dm \cdot \overline{Sm} \cdot \overline{Rm} + \overline{Dm} \cdot Sm \cdot Rm$ \\
		AND, ORR, XOR, TSA, TSO, TSX & $0$ (always cleared)                                            & $0$ (always cleared)                                                           \\
		\bottomrule
	\end{tabular}
	\caption{Carry and Overflow Flag Formulas}
	\label{tab:alu-flag-formulas}
\end{table}

$N$ and $Z$ are the same for every family: $N = Rm$ (the result's own sign bit), and $Z$ is set when the full
16-bit result is zero. \mnemonic{ADC} and \mnemonic{SBC} use the same formulas as \mnemonic{ADD} and
\mnemonic{SUB} respectively -- the incoming carry/borrow is folded into the addition or subtraction before
\texttt{Rm} (and the carry/borrow out) is evaluated, so no separate formula is needed for them.
\mnemonic{CMN}/\mnemonic{CNC}/\mnemonic{CMP}/\mnemonic{CPC}/\mnemonic{TSA}/\mnemonic{TSO}/\mnemonic{TSX} compute
the same flags as the corresponding
\mnemonic{ADD}/\mnemonic{ADC}/\mnemonic{SUB}/\mnemonic{SBC}/\mnemonic{AND}/\mnemonic{ORR}/\mnemonic{XOR} family
and simply discard the result.

\subsection{Manual Flag Update Control}

ALU instructions support manual control over how status flags are updated using the status override syntax. See
Section~\ref{sec:status-override} in Chapter~\ref{ch:shift-operations} for complete details.

\begin{itemize}
	\item \texttt{INSTR[A]} -- Update flags from ALU result (default behavior)
	\item \texttt{INSTR[S]} -- Update flags from shift result instead of ALU
	\item \texttt{INSTR[N]} -- Do not update status flags
	\item \mnemonic{MOVI} and \mnemonic{MOVR} do not accept \texttt{[S]}.
	\item AF encoding \texttt{11} (binary) is reserved and has no assembly syntax.
\end{itemize}

\begin{example}
	\begin{lstlisting}
; Update flags from shift operation
ADDI[S] r1, #0, LSL #3        ; Flags reflect (r1 << 3), not the ALU

; Preserve flags during operation
CMPR r2, r3                   ; Set comparison flags
ADDI[N] r4, #1                ; Increment without changing flags
BRAN|>= @branch_if_r2_gte_r3  ; Use flags from CMPR
	\end{lstlisting}
	\caption{Manual Status Flag Update Control}
\end{example}

\begin{instructionbox}{SHFT}{Shift with Status Update Meta-Instruction}
	\textbf{Applicability:} SIRC-1, all revisions

	\textbf{Assembles to:} \texttt{ORRI[S] rD, \#0, shift}. See Table~\ref{tab:alu-legal-forms} for the full family of legal forms.

	\begin{center}
		\begin{bytefield}[bitwidth=1.1em]{32}
			\bitheader{0-31} \\
			\bitbox{6}{\opcode{25}} &
			\bitbox{4}{rD} &
			\bitbox{8}{0x00} &
			\bitbox{1}{SO} &
			\bitbox{3}{ST} &
			\bitbox{4}{SA} &
			\bitbox{2}{10} &
			\bitbox{4}{Cond}
		\end{bytefield}
	\end{center}

	\textbf{Instruction Fields:}
	\begin{itemize}
		\item \textbf{Register (bits 25--22):} \texttt{rD}, the destination and shifted source register; any of the 16
		      registers, \texttt{0x0}--\texttt{0xF}.
		\item \textbf{Immediate (bits 21--14):} fixed at \texttt{0x00} by the meta-instruction.
		\item \textbf{SO, ST, SA (bits 13--6):} shift operand, type and count. Types: \texttt{NUL}, \texttt{LSL}, \texttt{LSR}, \texttt{ASL}, \texttt{ASR},
		      \texttt{RTL}, \texttt{RTR}; an immediate count is \texttt{0}--\texttt{15}; a register count is used in
		      full (16 or more clamps to a full shift for \texttt{LSL}/\texttt{LSR}/\texttt{ASL}/\texttt{ASR}, and is
		      taken modulo 16 for \texttt{RTL}/\texttt{RTR}) -- see Chapter~\ref{ch:shift-operations}.
		\item \textbf{AF (bits 5--4):} fixed at \texttt{10} (Shift) by the meta-instruction.
		\item \textbf{Condition field (bits 3--0):} any of the 16 condition-code encodings in
		      Table~\ref{tab:condition-code-encoding}.
	\end{itemize}

	\textbf{Syntax:}
	\begin{lstlisting}
SHFT rD, shift                ; rD = shifted rD; flags from shift
\end{lstlisting}

	\textbf{Operands:} \texttt{rD} is both the destination and shifted source register. \texttt{shift} may use any
	standard immediate or register shift count supported by short-immediate ALU instructions.

	\textbf{Operation:}
	\begin{verbatim}
shifted = shift(rD)
rD = shifted OR 0
SR = flags_from_shift_result
\end{verbatim}

	\textbf{Description:}

	Provides concise syntax for shifting a register value while taking status flags from the shifter result. It is not a
	separate CPU operation. The zero OR operation preserves the shifted source value, while \texttt{[S]} makes the status
	flags reflect the shift result instead of the OR result.

	\textbf{Flags:} Updated from the shifter result by default.

	\textbf{Write-back:} Inherits \mnemonic{ORRI} write-back to \texttt{rD}.

	\textbf{Exceptions:} Does not access memory and raises no instruction-specific faults.

	\textbf{Condition field:} If the condition is false, no shift result is written and status flags are preserved.

	\textbf{Timing:} Same as \mnemonic{ORRI}: 6 cycles, plus instruction-fetch wait states.

	\textbf{Privilege:} Available in protected mode and supervisor mode, except when it writes a
	privileged register (\reg{ah}, \reg{lh}, \reg{ph}, \reg{sh}); see Chapter~\ref{ch:exceptions}.

	\begin{example}
		\begin{lstlisting}
; Shift r1 left by 3 and update flags
SHFT r1, LSL #3               ; ORRI[S] r1, #0, LSL #3

; Shift right and test result
SHFT r3, LSR #2               ; r3 = r3 >> 2
BRAN|== @zero_result          ; Branch if shifted result is zero
		\end{lstlisting}
		\caption{Shifting and Testing with SHFT}
	\end{example}

	\textbf{Notes:}
	\begin{itemize}
		\item Immediate shift counts are 0--15; the assembler rejects a larger literal. A register shift count is used in full (16 or
		      more clamps to a full shift for \texttt{LSL}/\texttt{LSR}/\texttt{ASL}/\texttt{ASR}, and is taken modulo 16 for
		      \texttt{RTL}/\texttt{RTR}) -- see Chapter~\ref{ch:shift-operations}.
		\item All six shift types are supported, plus \mnemonic{NUL}: NUL, LSL, LSR, ASL, ASR, RTL, and RTR. \texttt{SHFT rD, NUL
			      \#0} sets the flags from the unshifted value of \texttt{rD}.
	\end{itemize}
\end{instructionbox}

		\begin{bytefield}[bitwidth=1.1em]{32}

	\end{itemize}

	\begin{lstlisting}
MOVI rD, #imm16                ; rD = imm16
MOVR rD, rS                    ; rD = rS
\end{lstlisting}

result = operand
destination = result
SR.N = result[15]

SR.C = 0
SR.V = 0
\end{verbatim}

	\textbf{Description:}

	The ALU passes the second operand straight through to the destination; the first operand is ignored. This is the
	primary way to load constants into registers or move data between them. Opcode \opcode{27} has no public assembly
	syntax and is undocumented.

	\textbf{Flags:} N Z (C and V cleared)

	\textbf{Write-back:} If the condition is true, writes the loaded or copied value to \texttt{rD}.

	\textbf{Exceptions:} Does not access memory in these forms and raises no instruction-specific faults.

	\textbf{Condition field:} If the condition is false, no result is written and status flags are preserved.

	\textbf{Timing:} 6 cycles, plus instruction-fetch wait states.

	\textbf{Privilege:} Available in protected mode and supervisor mode, except when it writes a
	privileged register (\reg{ah}, \reg{lh}, \reg{ph}, \reg{sh}); see Chapter~\ref{ch:exceptions}.

	\begin{example}
		\begin{lstlisting}
; Move a constant
MOVI r1, #1234             ; r1 = 1234

; Copy register
MOVR r2, r1                ; r2 = r1

; Move, then shift with an ALU instruction
MOVI r3, #1
ADDI r3, #0, LSL #8        ; r3 = (r3 << 8) + 0 = 256

; Zero a register
MOVI r4, #0                ; r4 = 0

; Build a large constant
MOVI r5, #0x12
ADDI r5, #0, LSL #8        ; r5 = (r5 << 8) + 0 = 0x1200
ORRI r5, #0x34             ; r5 = 0x1234
		\end{lstlisting}
		\caption{Moving Constants and Copying Registers}
	\end{example}

	\textbf{Notes:}
	\begin{itemize}
		\item Most efficient way to move data between registers
		\item For 16-bit constants, use \mnemonic{MOVI}
		\item To build shifted or composite constants, combine \mnemonic{MOVI} with ALU instructions such as \mnemonic{ADDI} or
		      \mnemonic{ORRI}
	\end{itemize}
\end{instructionbox}

			\bitbox{6}{\opcode{3D}} &
			\bitbox{4}{ignored} &
			\bitbox{4}{rS1} &
			\bitbox{4}{rS2} &
			\bitbox{1}{SO} &
			\bitbox{3}{ST} &
			\bitbox{4}{SA} &
			\bitbox{2}{SUS} &
			\bitbox{4}{Cond}
		\end{bytefield}
	\end{center}

	\textbf{Instruction Fields:}
	\begin{itemize}
		\item \textbf{rS (Reg, bits 25--22), immediate and short-immediate forms:} source register; any of the 16 registers,
		      \texttt{0x0}--\texttt{0xF}. No destination register is written.
		\item \textbf{ignored (R1, bits 25--22), register form only:} no destination register is written, so the CPU ignores
		      this field. The assembler encodes a copy of \texttt{rS1}.
		\item \textbf{rS1 (R2, bits 21--18) and rS2 (R3, bits 17--14), register form only:} first and second source registers.
		\item \textbf{imm16 (Immediate Value, bits 21--6) or imm8 (Imm, bits 21--14):} 16-bit value (immediate form) or 8-bit
		      value zero-extended to 16 bits (short-immediate form).
		\item \textbf{SO, ST, SA (bits 13--6, short-immediate and register forms only):} shift operand, type and count. Types:
		      \texttt{NUL}, \texttt{LSL},
		      \texttt{LSR}, \texttt{ASL}, \texttt{ASR}, \texttt{RTL}, \texttt{RTR}; an immediate count is
		      \texttt{0}--\texttt{15}; a register count is used in full (16 or more clamps to a full shift for \texttt{LSL}/\texttt{LSR}/\texttt{ASL}/\texttt{ASR}, and is taken modulo 16 for \texttt{RTL}/\texttt{RTR}) -- see Chapter~\ref{ch:shift-operations}.
		\item \textbf{SUS (AF, bits 5--4):} status update source: \texttt{00} = None, \texttt{01} = Alu (default), \texttt{10} = Shift, \texttt{11} =
		      Reserved.
		\item \textbf{Condition field (bits 3--0):} any of the 16 condition-code encodings in
		      Table~\ref{tab:condition-code-encoding}.
	\end{itemize}

	\textbf{Syntax:}
	\begin{lstlisting}
TSOI rS, #imm16                ; Test rS | imm16
TSOI rS, #imm8, shift          ; Test shift(rS) | imm8
TSOR rS1, rS2                  ; Test rS1 | rS2
TSOR rS1, rS2, shift           ; Test shift(rS1) | rS2
\end{lstlisting}

	\textbf{Operands:} Same source operand forms as \mnemonic{ORR}. The result is used only for status flag updates; no
	destination register is written.

	\textbf{Operation:}
	\begin{verbatim}
result = operand1 OR operand2
; Result is discarded, only flags updated
SR.N = result[15]
SR.Z = (result == 0)
SR.C = 0
SR.V = 0
\end{verbatim}

	\textbf{Description:}

	Performs bitwise OR but discards the result, only updating flags. In short immediate format with shift, the source
	register is shifted before ORing with the immediate. The zero flag is set only when every bit of both operands is zero,
	so a single \mnemonic{TSOR} tests whether two registers are both zero.

	\textbf{Flags:} N Z (C and V cleared)

	\textbf{Write-back:} None. The OR result is discarded after status flags are updated.

	\textbf{Exceptions:} Does not access memory and raises no instruction-specific faults.

	\textbf{Condition field:} If the condition is false, no status flags are updated.

	\textbf{Timing:} 6 cycles, plus instruction-fetch wait states.

	\textbf{Privilege:} Available in protected mode and supervisor mode. This instruction only reads the register named
	by its register field and never writes it, so it does not raise a privilege-violation fault even when that field
	names a privileged register such as \reg{ah} (for example, \texttt{TSOI ah, \#0}); see
	Chapter~\ref{ch:exceptions}.

	\begin{example}
		\begin{lstlisting}
; Test if the 32-bit value in r1:r2 is zero
TSOR r1, r2
BRAN|== @is_zero           ; Branch if both words are zero

; Test if either of two flag words has bit 15 set
TSOR r3, r4
BRAN|NS @flag_set
		\end{lstlisting}
		\caption{Testing Two Values at Once with TSO}
	\end{example}

	\textbf{Notes:}
	\begin{itemize}
		\item Does not modify any register, only flags
		\item Z=1 means every bit of both operands is 0
		\item Z=0 means at least one bit is 1 in one of the operands
		\item N=1 means bit 15 is set in at least one of the operands
		\item More efficient than ORR into a scratch register for testing whether two values are both zero
	\end{itemize}
\end{instructionbox}

	\textbf{Syntax:}
	\begin{lstlisting}
TSXI rS, #imm16                ; Test rS ^ imm16
TSXI rS, #imm8, shift          ; Test shift(rS) ^ imm8
TSXR rS1, rS2                  ; Test rS1 ^ rS2
TSXR rS1, rS2, shift           ; Test shift(rS1) ^ rS2
\end{lstlisting}

	\textbf{Operands:} Same source operand forms as \mnemonic{XOR}. The result is used only for status flag updates; no
	destination register is written.

	\textbf{Operation:}
	\begin{verbatim}
result = operand1 XOR operand2
; Result is discarded, only flags updated
SR.N = result[15]
SR.Z = (result == 0)
SR.C = 0
SR.V = 0
\end{verbatim}

	\textbf{Description:}

	Performs bitwise XOR but discards the result, only updating flags. In short immediate format with shift, the source
	register is shifted before XORing with the immediate. Used to test if bits match a specific pattern or to compare
	values for equality. Z=1 indicates the values are identical.

	\textbf{Flags:} N Z (C and V cleared)

	\textbf{Write-back:} None. The XOR result is discarded after status flags are updated.

	\textbf{Exceptions:} Does not access memory and raises no instruction-specific faults.

	\textbf{Condition field:} If the condition is false, no status flags are updated.

	\textbf{Timing:} 6 cycles, plus instruction-fetch wait states.

	\textbf{Privilege:} Available in protected mode and supervisor mode. This instruction only reads the register named
	by its register field and never writes it, so it does not raise a privilege-violation fault even when that field
	names a privileged register such as \reg{ah} (for example, \texttt{TSXI ah, \#0}); see
	Chapter~\ref{ch:exceptions}.

	\begin{example}
		\begin{lstlisting}
; Test if r1 equals specific value
TSXI r1, #0x1234           ; Test r1 ^ 0x1234
BRAN|== @is_0x1234         ; Branch if r1 == 0x1234

; Test if two registers are equal
TSXR r1, r2                ; Test r1 ^ r2
BRAN|== @registers_equal   ; Branch if r1 == r2

; Test if bit pattern matches
ANDI r3, #0x00FF           ; Mask to low byte
TSXI r3, #0x00AA           ; Test if low byte == 0xAA
BRAN|== @pattern_match
		\end{lstlisting}
		\caption{Equality and Pattern Testing with TSX}
	\end{example}

	\textbf{Notes:}
	\begin{itemize}
		\item Does not modify any register, only flags
		\item Z=1 means values are identical (all bits match)
		\item Can be used as equality test (alternative to CMP for == only)
		\item More efficient than XOR + CMP for simple equality tests
	\end{itemize}
\end{instructionbox}

\section{Summary}

The ALU instructions form the computational core of the SIRCIS instruction set. Key points:

\begin{itemize}
	\item All ALU operations work only on registers (load/store architecture)
	\item Three format variants provide flexibility (immediate, short+shift, register)
	\item Test variants (CMN, CNC, CMP, CPC, TSA, TSO, TSX) allow non-destructive testing
	\item Shift operations can be combined with ALU ops for powerful single-instruction operations
	\item Consistent flag behavior makes conditional execution predictable
\end{itemize}
