\chapter{Instruction Timing}
\label{appendix:timing}

\section{Overview}

Most SIRCIS instructions follow the six-stage execution phase model and complete in 6 clock cycles when no bus wait
states are required. A bus operation may hold the current phase until it is acknowledged, adding wait cycles without
adding execution phases. Coprocessor calls are the exception: the dispatched coprocessor occupies at least one further
slot after the six-phase call. This fixed execution sequence greatly simplifies software development and hardware
design. See the \textit{SIRC-1 Hardware Reference Manual} for the bus signal timing, wait-state, and response-priority
rules.

\section{Six-Stage Execution Phases}

For a detailed description of each phase, see Chapter~\ref{ch:cpu-architecture}.

\begin{enumerate}
	\item \textbf{Instruction Fetch (High Word)} -- 1 cycle
	\item \textbf{Instruction Fetch (Low Word)} -- 1 cycle
	\item \textbf{Decode and Register Fetch} -- 1 cycle
	\item \textbf{Execute and Address Calculation} -- 1 cycle
	\item \textbf{Memory Access} -- 1 cycle
	\item \textbf{Write Back} -- 1 cycle
\end{enumerate}

The cycle counts in this appendix assume that every bus operation is acknowledged without a wait state. For

dispatch to the DMA unit and takes only 6 cycles.

\subsection{Exception and Fault Timing}
\label{sec:exception-and-fault-timing}

A hardware-exception or fault dispatch occupies one 6-cycle slot: the vector's high word is fetched at phase 0, the low
word at phase 1, and entry to the handler is committed at phase 3. A latched interrupt is dispatched at the next phase
0 at which the CSR is empty and no coprocessor is active (Section~\ref{sec:interrupt-latency}). The worst-case latency
from the interrupt request to the handler's first instruction fetch is the time the current instruction still needs
plus 6 cycles to dispatch, with the current instruction being as long as its entry in
Table~\ref{tab:instruction-timing} allows:

\begin{itemize}
	\item Most instructions: 6 + 6 = 12 cycles.
	\item A coprocessor call: 12 + 6 = 18 cycles, because its dispatch slot completes first.
	\item \mnemonic{DMAR} or \mnemonic{DMAW} with a count of 7: 18 + 6 = 24 cycles.
	\item \mnemonic{DMAT} with a count of 255: 521 + 6 = 527 cycles (about 22 microseconds at 24~MHz), because a DMA
	      transfer cannot be interrupted.
\end{itemize}

These figures assume no bus wait states. Reset holds \texttt{RSTO} for 6 cycles before the reset-vector fetch.

A retryable fault cancels the faulting instruction at the phase that detects it. The six-phase sequence is never cut
short: the instruction's remaining phases still run, but as no-ops that perform no bus access and commit no results, so
the cancelled instruction occupies its full six cycles. Alignment is detected before phase 0 and issues no bus cycle;
its dispatch slot takes the place of the instruction, so it costs no extra cycles. Privilege Violation is detected at
phase 2 for a write to a privileged register field and for a supervisor-only coprocessor operation, at phase 3 for an
\mnemonic{EXCP} vector below \texttt{0x60}, and at phase 5 for an address-pair write that would change a high word.
Segment Overflow is detected at phase 3. Bus and Bus Protection faults are detected at the phase that acknowledges the
failing bus access. The first fault detected cancels the instruction, and the checks belonging to its remaining phases
are not made, so an instruction that meets two fault conditions raises the one detected in the earlier phase. In phase
3, a privilege violation takes precedence over a segment overflow, and an instruction that wraps more than one address
(the effective address, the auto-update or the program counter) raises a single segment-overflow fault. In every other
case the exception-unit dispatch slot begins at the next phase 0, after the remaining phases have run. Alignment, Bus,
Bus Protection, Invalid Opcode, Privilege Violation, and Segment Overflow all save the address of the faulting
instruction and are retryable. The instruction trace fault is raised after its instruction has completed, so nothing is
cancelled.

A bus or protection fault during an exception-vector fetch is handled the same way as one during an instruction fetch.
The dispatch slot in progress is cancelled and its remaining phases run as no-ops, and the dispatch for the new fault
begins at the next phase 0. Only reset restarts the phase sequence immediately: it discards all state and returns to
phase 0.

\section{Conditional Execution}

When a conditional instruction's condition is not met:
\begin{itemize}
	\item All six phases still occur and consume one cycle each
	\item The execute, memory-access, and write-back phases perform no operation: no effective address is computed, no
	      data-address \texttt{SR.A} overflow check is made, and no data bus cycle is driven
	\item The program-counter advance is still checked: with \texttt{SR.A} set, a skipped instruction in the last instruction
	      slot of a segment raises a segment-overflow fault in phase 3 (Section~\ref{sec:segment-overflow-fault})
	\item No register, memory, or address-register update occurs
	\item Status flags are not updated
\end{itemize}

This means conditional instructions do not branch and avoid control-flow stalls, but failed conditions still consume
execution time.

\section{Program Timing Examples}

\subsection{Simple Loop}
\begin{lstlisting}
; Process 10 elements (assuming no bus wait states)
MOVI r7, #10                  ; 6 cycles
:loop
    LOAD r1, (#0, a)+         ; 6 cycles
    ADDI r1, #1               ; 6 cycles
    STOR (#-1, a), r1         ; 6 cycles
    SUBI r7, #1               ; 6 cycles
    BRAN|!= @loop             ; 6 cycles
; Total per iteration: 30 cycles
; Total for 10 iterations: 6 + (10 * 30) = 306 cycles
\end{lstlisting}

\subsection{Function Call Overhead}
\begin{lstlisting}
; Call function
LJSR a                        ; 6 cycles

; Function body executes...

; Return
RETS                          ; 6 cycles
; Total overhead: 12 cycles
\end{lstlisting}

\subsection{Conditional Block}
\begin{lstlisting}
CMPR r1, r2                   ; 6 cycles
ADDR|HI r3, r4, r5            ; 6 cycles (exec if r1 > r2)
ADDR|LO r3, r6, r7            ; 6 cycles (exec if r1 <= r2)
; Total: 18 cycles (one conditional executes, one doesn't)
\end{lstlisting}

\section{Performance Considerations}

\subsection{No Pipeline Stalls}

The SIRC-1 does not implement pipelining in the traditional sense where multiple instructions are in flight
simultaneously. Instead:

\begin{itemize}
	\item Each instruction completes fully before the next begins
	\item No data hazards or phase bubbles
	\item No branch prediction penalties
	\item Base execution time is predictable before bus wait states are considered
\end{itemize}

\subsection{Memory Access}

\begin{itemize}
	\item Instruction fetch, data memory access, and exception vector fetch each occupy one execution phase per 16-bit word
	      transferred.
	\item If the external memory system has not acknowledged the transfer (\texttt{BACK}) and has not aborted it with a bus error
	      (\texttt{BERR}) or bus protection error (\texttt{BPER}), the CPU holds that phase until the transfer is acknowledged.
	\item Each wait state adds one clock cycle to the instruction
	\item Every instruction performs two instruction-fetch bus accesses; a load or store adds one data access; an exception or
	      fault dispatch adds two exception-vector-fetch accesses; a coprocessor dispatch performs no bus access of its own. A
	      system that inserts $w$ wait states per access therefore adds $2w$ cycles to an ALU instruction and $3w$ cycles to a
	      load or store.
\end{itemize}

\subsection{Optimization Guidelines}

\begin{enumerate}
	\item \textbf{Use conditional execution for short sequences}
	      \begin{lstlisting}
; Instead of:
CMPR r1, r2
BRAN|LO @skip
ADDI r3, #1
:skip

; Use:
CMPR r1, r2
ADDI|HI r3, #1             ; Saves branch overhead
    \end{lstlisting}

	\item \textbf{Combine operations with shifts}
	      \begin{lstlisting}
; Instead of:
ADDR r1, r2, r2            ; r1 = 2 * r2
ADDR r1, r1, r2            ; r1 = 3 * r2

; Use:
ADDR r1, r2, r2, LSL #1    ; Multiply by 3 in one instruction
    \end{lstlisting}

	\item \textbf{Use post-increment/pre-decrement for iteration}
	      \begin{lstlisting}
; Instead of:
LOAD r1, (#0, a)
ADDI al, #1

; Use:
LOAD r1, (#0, a)+          ; Same result, fewer cycles
    \end{lstlisting}

	\item \textbf{Loop unrolling reduces overhead}
	      \begin{lstlisting}
; Instead of processing one item per iteration,
; process multiple items to reduce branch overhead
:loop
    LOAD r1, (#0, a)+
    LOAD r2, (#0, a)+
    LOAD r3, (#0, a)+
    LOAD r4, (#0, a)+
    ; Process 4 items...
    SUBI r7, #4
    BRAN|HI @loop
    \end{lstlisting}
\end{enumerate}

\section{Theoretical Performance}

At a given clock frequency:

\begin{itemize}
	\item \textbf{Instructions per second:} $f_{clock} / 6$
	\item \textbf{At 10 MHz:} $\approx$ 1.67 million instructions/second
	\item \textbf{At 24 MHz (maximum rated clock):} $\approx$ 4.0 million instructions/second
\end{itemize}

These are theoretical maximums assuming perfect code with no inefficiencies.

The SIRC-1's fixed 6-cycle execution trades peak throughput for predictability: every ordinary instruction takes the
same number of cycles regardless of the operation or operands, which is simpler to implement in hardware and easier to
reason about than a variable-cycle-count design.
