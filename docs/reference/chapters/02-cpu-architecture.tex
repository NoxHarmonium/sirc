\chapter{CPU Architecture}
\label{ch:cpu-architecture}

\section{Overview}

The SIRC-1 CPU architecture takes advantage of the regularity of the SIRCIS instruction set to execute ordinary
instructions through a common six-phase execution sequence.

Control signals are generated directly from the decoded instruction and current execution phase, eliminating the need
for separate microprograms for individual instructions.

This approach is intended to support compact, hardwired control logic, potentially reducing transistor count and die
area compared with microprogrammed implementations. Eliminating microinstruction fetch delays may also permit higher
clock frequencies.

\section{Six-Stage Execution Phases}

Most SIRC-1 instructions follow a six-phase execution model and complete in 6 clock cycles when no bus wait states are
required.

A phase that performs a bus operation may be held until the bus acknowledges it. DMA commands dispatch through the
normal six-phase coprocessor-call path and then hold instruction fetch while the DMA unit completes its transfer.

Each address-register pair, including \reg{p}, splits into a high half and a low half, written \reg{Xh} and \reg{Xl}
(for example \reg{ph} and \reg{pl}); Chapter~\ref{ch:registers} describes this split in detail.

\begin{description}
	\item[Phase 0: Instruction Fetch (High Word)] -- 1 cycle
	      \begin{itemize}
		      \item Fetch bits 31--16 from memory address in \reg{p}
		      \item \reg{p} is unchanged
	      \end{itemize}

	\item[Phase 1: Instruction Fetch (Low Word)] -- 1 cycle
	      \begin{itemize}
		      \item Fetch bits 15--0 from memory address in \reg{p} + 1
		      \item Instruction is now fully available for decode
		      \item \reg{p} is unchanged
	      \end{itemize}

	\item[Phase 2: Decode and Register Fetch] -- 1 cycle
	      \begin{itemize}
		      \item Decode instruction opcode and operands
		      \item Read source registers (optionally shifted)
		      \item Evaluate condition codes
		      \item Advance \reg{pl} by 2 to the address of the next instruction (\reg{ph} is unchanged)
	      \end{itemize}

	\item[Phase 3: Execute and Address Calculation] -- 1 cycle
	      \begin{itemize}
		      \item Perform ALU operation, and/or
		      \item Calculate effective memory address
	      \end{itemize}

	\item[Phase 4: Memory Access] -- 1 cycle
	      \begin{itemize}
		      \item Read from memory (LOAD), or
		      \item Write to memory (STOR), or
		      \item No operation (register-only instructions)
	      \end{itemize}

	\item[Phase 5: Write Back] -- 1 cycle
	      \begin{itemize}
		      \item Write result to destination register
		      \item Update status register flags if applicable
		      \item Update address registers for post-increment/pre-decrement
	      \end{itemize}
\end{description}

\subsection{Control Unit (CU)}

The Control Unit sits at the heart of the SIRC-1 CPU, coordinating all other functional units throughout the
instruction execution phases. It decodes instructions and generates control signals that orchestrate data movement and
operations across the CPU.

Key responsibilities include:
\begin{itemize}
	\item Instruction fetch and decode
	\item Execution phase coordination
	\item Control signal generation for all functional units
	\item Condition code evaluation for conditional execution
	\item Fetching exception vectors on behalf of the exception coprocessor
	\item Dispatching coprocessor commands through the coprocessor select register (CSR)
\end{itemize}

\subsection{Coprocessors and the Coprocessor Select Register}
\label{sec:coprocessors-and-csr}

Operations are carried out by coprocessors. The processing unit (coprocessor \texttt{0x0}) executes ordinary
instructions using the ALU, AU and barrel shifter described below. Other coprocessors, such as the exception
coprocessor (\texttt{0x1}), carry out specialized operations on request. Every coprocessor reaches the register file
and the bus interface through the coprocessor interface, and only one is active at a time.

The coprocessor select register (CSR) holds the pending coprocessor command: it tells the CU which coprocessor runs
next and what it should do. It is a 16-bit internal register: bits 15--12 hold the coprocessor ID, bits 11--8 the
coprocessor operation, and bits 7--0 an operand or vector. A \mnemonic{COPI} or \mnemonic{COPR} instruction writes its
command operand to the CSR during write-back. The CU consumes the CSR by dispatching the command to the selected
coprocessor in a further six-phase slot, and that coprocessor stays active until the command completes. While nothing
is pending the CSR is \texttt{0x0000}, which selects the processing unit, so the CPU carries on running the program.
Chapter~\ref{ch:coprocessor} describes the instructions and Section~\ref{sec:coprocessor-select-register} the
register's layout.

The exception coprocessor never overwrites a pending command. It keeps its own record of the exception it wants to
service, and loads the CSR with a hardware interrupt, software exception or trace fault only when the CSR is empty and
no coprocessor is active. A fault raised by the call or its command is the exception: it ends the command and is
dispatched at once. A coprocessor call is therefore part of its instruction: its dispatch slot, and the command it
starts, complete before any pending interrupt or instruction trace fault is taken, except that a traced \mnemonic{EXCP}
takes its trace fault first (Section~\ref{sec:interrupt-latency}).

\subsection{Arithmetic Logic Unit (ALU)}

The ALU performs all arithmetic and logical operations on register values. It supports the following operations:

\begin{itemize}
	\item \textbf{Arithmetic:} Addition, Subtraction (with and without carry)
	\item \textbf{Logical:} AND, OR, XOR
	\item \textbf{Comparison:} Test and compare operations
	\item \textbf{Status Flag Generation:} Carry, Overflow, Negative, Zero
\end{itemize}

The ALU operates on data from the Register File (after optional shifting), along with immediate constants decoded from
instructions and outputs results back to the Register File. It cannot operate on data stored in memory directly.

\subsection{Addressing Unit (AU)}

The Addressing Unit calculates memory addresses and manages address-related operations. It is responsible for:

\begin{itemize}
	\item Computing effective addresses from base + displacement
	\item Computing the updated base address for pre-decrement and post-increment
	\item Detecting segment overflow in the address calculation, and when an instruction would use a program-counter advance that
	      wraps the segment
	\item Presenting calculated addresses to the address bus
\end{itemize}

The AU works in parallel with the ALU during the execution phase, allowing address calculation to occur simultaneously
with ALU operations.

\subsection{Register File}

The Register File contains all CPU registers organized into three categories:

\begin{itemize}
	\item \textbf{General-Purpose Registers:} \reg{r1}--\reg{r7}
	\item \textbf{Address Register Pairs:} \reg{l} (link), \reg{a} (address), \reg{s} (stack), \reg{p} (program counter)
	\item \textbf{Status Register:} \reg{sr}
\end{itemize}

The Register File allows the ALU, AU, and Control Unit to read and write registers as needed during each execution
phase. All registers are 16 bits wide, though address register pairs can be combined to form 24-bit addresses.

\subsection{Barrel Shifter}

A barrel shifter sits between the Register File and the ALU, enabling efficient bit manipulation operations.

The barrel shifter supports logical shift left (\mnemonic{LSL}), logical shift right (\mnemonic{LSR}), arithmetic shift
left (\mnemonic{ASL}), arithmetic shift right (\mnemonic{ASR}), rotate left (\mnemonic{RTL}), and rotate right
(\mnemonic{RTR}). Shift amounts can be specified as immediate values or dynamically from register contents.

The shift is applied to the first source operand when fetching the source registers for an instruction. Shifts cannot
be applied to the result or any other source operand.

\subsection{Exception Coprocessor}

The Exception Coprocessor (coprocessor ID \texttt{0x1}) manages faults, hardware interrupts, software exceptions and
reset. When an exception is pending, it takes control of the processor and diverts execution to the handler through a
vector. It is responsible for:

\begin{itemize}
	\item Receiving faults, interrupt requests and reset
	\item Comparing each exception's priority with the current exception level
	\item Canceling an instruction that raises a retryable fault, so its remaining phases run as no-ops
	\item Holding the link registers that save the return address, status register and exception level
	\item Writing the exception to service into the coprocessor select register (CSR)
\end{itemize}

The Control Unit runs the resulting entry sequence through the normal execution phases. The exception instructions
(\mnemonic{EXCP}, \mnemonic{RETE}, \mnemonic{WAIT}, \mnemonic{RSET}, \mnemonic{ETFR} and \mnemonic{ETTR}) reach the
coprocessor as coprocessor calls. Chapter~\ref{ch:exceptions} describes exception handling in detail.

\section{Design Characteristics}

\subsection{Hardwired Control Implementation}

The SIRC-1 is designed to support hardwired control logic without requiring a microcode engine.

A six-phase state machine coordinates instruction execution, with combinational logic performing instruction decoding,
arithmetic, address calculation and control signal generation. Clocked registers retain architectural and intermediate
execution state between phases.

Combined with the regularity of the SIRCIS instruction set, this approach offers several potential advantages:

\begin{itemize}
	\item A deterministic, fixed execution sequence
	\item Reduced control logic complexity and hardware requirements
	\item Predictable instruction behavior and execution timing
\end{itemize}

\subsection{Fixed Execution Sequence}

Ordinary instructions execute in exactly 6 phases, regardless of instruction type or operands, and complete in 6 clock
cycles when no bus wait states are required. This design choice reduces the complexity of instruction sequencing and
simplifies execution timing.

Once an instruction has started, the sequence is never cut short. If a retryable fault cancels an instruction, its
remaining phases still run, but as no-ops that access no bus and commit no results, and the exception dispatch begins
at the next phase 0. The alignment fault is the exception: it is detected at phase 0, before the instruction starts,
and its dispatch begins at that same phase 0 (Section~\ref{sec:alignment-fault}). Hardware interrupts, software
exceptions and the instruction trace fault let the current instruction finish before they are dispatched.

Coprocessor calls are the exception: the processing-unit instruction takes six cycles and the coprocessor dispatch
normally takes a further six. A call whose condition is false, or that names coprocessor \texttt{0x0}, has no dispatch
slot and takes only six cycles. Some coprocessors, such as the DMA coprocessor, can additionally hold instruction fetch
until the operation completes.

\subsection{Parallel Functional Units}

The ALU and AU operate in parallel during phase 3 (Execute and Address Calculation), allowing address calculation to
proceed simultaneously with arithmetic operations. This parallelism enables efficient execution of memory reference
instructions without additional clock cycles.

\section{External Interface}

The SIRC-1 CPU communicates with memory and peripherals over an external bus, and receives interrupt and reset requests
from external hardware. How those signals are carried (the package, pinout, electrical characteristics and bus timing)
is implementation-specific and is described in the \hwmanual{}. When the reset request (\texttt{RSTI}) is raised, the
CPU abandons the current instruction or bus wait and restarts the phase sequence at phase 0 with the reset-vector fetch
(Section~\ref{sec:reset-vector-fetch}).
